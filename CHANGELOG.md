# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

**Upgrading from 1.2.0:**
- Every user signs in once after the upgrade: sessions and tokens issued by earlier builds are no longer accepted.
- On a fresh production install the first (admin) account can only be registered with `REGISTRATION_BOOTSTRAP_TOKEN`; the sign-up form has a "Setup token" field for it.
- Run the migrations (`alembic upgrade head`; the container does this at start): revision 013 adds `users.token_version` and `users.must_change_password`.
- Audit log: no action needed. Entries written by earlier builds were never linked to each other; they are still verified against their own signatures, and chain linkage is enforced from the first entry this build writes. A production instance that could not restart because of the old chain now starts with `AUDIT_HALT_ON_TAMPERING` left on.
- Connectors: sync now requires a folder or an explicit whole-account confirmation. Reconnect Microsoft and Google connections to move them to the narrower read-only scopes (existing grants keep the old scope until then). Filevine is off until `FILEVINE_ENABLED=true` and is admin-only.
- Backups require `BACKUP_ENCRYPTION_KEY` or an explicit `BACKUP_ALLOW_UNENCRYPTED=true`.
- Bundled Redis now runs `noeviction`; if you run your own Redis, do not use an LRU policy on the instance that holds revocations and lockouts.

### Added
- `DELETE /user/keys/{provider}` removes one of your stored API keys (there was no way to delete a key once saved). `DELETE /contract-analysis/analyses/{id}` and `DELETE /authority-map/{run_id}` let the owner delete a stored analysis or authority map together with the contract text derived from it.
- `matters.manage` permission ("Create & share matters", admin and attorney by default) and `GET /matters/all`, an admin-only listing of every shared matter with its owner and member count.
- Production-mode smoke test (`scripts/smoke_production.py`, CI job `production-smoke`): boots the backend with `DEBUG` off against Postgres and Redis, registers the first admin, reads the admin-only system endpoints, then restarts the process over the data the first boot wrote, signs in again and verifies the audit chain. The unit tests run with `DEBUG=true` on SQLite, so nothing exercised these paths before.
- `backend/requirements-dev.txt` pins the test, lint and security tooling (pytest, pytest-cov, ruff, mypy, bandit, pip-audit). A plain `python -m pytest` no longer needs `pytest-cov`: the coverage flags moved from `pyproject.toml` to the CI command.
- `scripts/generate_notice.py` regenerates `NOTICE.md` from `backend/requirements.lock` and `frontend/package-lock.json` (and refuses a GPL/AGPL/SSPL dependency).
- `SUPPORT.md`, an issue-template chooser that routes vulnerability reports to private reporting, a gitleaks pre-commit hook, and Dependabot update PRs for pip, npm, GitHub Actions and the Docker base images.
- A version tag (`v*`) now builds and publishes a version-tagged image; every image is built with `SOURCE_COMMIT`, so `/health` reports the running commit (to an admin; the public response carries no version) instead of `unknown`.
- `EMBEDDING_BASE_URL` sends embeddings to an OpenAI-compatible server you run (with `EMBEDDING_MODEL`, and `EMBEDDING_DIMENSIONS` for Pinecone), so document text can be embedded on your own network. Until now embeddings always went to a hosted provider, even with a local chat endpoint.
- Password flows in the UI: a `/reset-password` page for the emailed link (it previously led nowhere), a Change Password dialog under Settings → Security, and a forced password change for invited users. The sign-up form takes the first-admin setup token.
- Admin UI: deactivate/reactivate, delete, export, force sign-out and two-factor reset in the Users tab; an Audit Log tab with filters, an integrity check and JSONL export (`GET /admin/audit/export`); active sessions and "Sign out everywhere" under Security; a Remove button for stored API keys. Backing endpoints: `POST /admin/users/{id}/sessions/revoke`, `POST /admin/users/{id}/mfa/reset`.
- `REQUIRE_MFA` (off by default) makes two-factor enrolment mandatory before the API can be used; `AUDIT_FAIL_CLOSED` (off by default) fails a request whose audit entry cannot be written.
- `GET /admin/users/{id}/export` now returns the user's saved settings, chat sessions with messages, contract analyses with their findings, authority maps, workspace sessions and matters, alongside the profile and document metadata it returned before.
- The Authority Map view is linked from the sidebar; chat has a Cancel button; a 404 page.

### Fixed
- `GET /settings/prompts/defaults` always answered 500 (it called methods that do not exist), so "reset to default" could not load a prompt; its test accepted the 500. `POST /settings/clear` reported a failure as HTTP 200 with `status: "error"`; a clear that removes nothing is now an error, and one that removes only some documents answers `status: "partial"` with the count that was kept.
- "Re-index" in Settings answered 403 for everyone but admins although it only touches the caller's own documents. Re-index and clear now follow the document permissions (upload / delete).
- Downloading a document whose filename has characters outside Latin-1 (an en dash, curly quotes, CJK) answered 500. `Content-Disposition` now carries an ASCII fallback plus the RFC 5987 `filename*` form.
- An uploaded logo could never load: it was saved into the (encrypted, never served) document upload directory under a `/static/uploads/` URL that no route answered. Logos are stored in their own directory and served by `GET /branding/assets/{name}`; logos uploaded by earlier builds are picked up from the old location.
- The API reported version `1.0.0` in `/`, `/metrics` and the OpenAPI document; all three now report the release version from one constant. The app name is "CaseCite" (was "CaseCite RAG").
- `/ready` answered 503 and `/health` "degraded" on an instance with no server-level AI key, although bring-your-own-key is a supported configuration; a missing vector store was reported "healthy"; a driver-specific exception in a probe became a 500.
- Judge Intel error logs contained the literal text `{judge_id}` instead of the id.
- Tests wrote into the real `backend/data` directory (audit logs, sessions, the SQLite database) and, with a real `OPENAI_API_KEY` in `.env`, called OpenAI on every app start-up. The suite now runs against a throwaway data directory with dummy keys and outbound DNS blocked, and `pytest` starts without `pytest-cov` (CI passes the coverage flags itself).
- Research chat treated ordinary English as Boolean search syntax: "What happens if rent is not paid on time?" excluded every passage containing "paid", and stop words and any `word:value` token were stripped from the text that was embedded. `AND`/`OR`/`NOT` are now operators only in uppercase (and `-term` excludes); the question is embedded as typed; only known filter fields (`court:`, `type:`, `after:` …) are parsed out. `OR`, which was parsed and then ignored, now works.
- Chat scoped to selected files or a folder did no retrieval: it returned the first chunks in storage order (with several files, mostly the start of the first), ignored the question, and labelled each passage "100%". Scoped chat now runs the same semantic search restricted to the selected documents, guarantees every selected file a share of the passages, and reports the measured similarity.
- A chat scope that matched no indexed documents (an empty or still-indexing folder) silently searched the whole knowledge base — a question about one client's folder could be answered from another's files. It now answers that the scope has no indexed documents.
- Provider and CourtListener failures in chat (rate limit, rejected key, timeout, HTTP error) returned a generic 500 — including for questions that only needed the user's documents. They now produce an answer that says what failed; a CourtListener outage means "no case law this time".
- A Claude or Gemini model selected without the matching API key was sent to the OpenAI client; it is now a clear "add the key or choose another model" message. The selected Gemini model is the one used (every Gemini choice ran on one fixed model). The helper passes around an answer (routing, case-law screening, claim grounding, citation reasoning, per-file analysis) run on the provider of the user's chosen model instead of always on OpenAI.
- Embeddings: a user with only a Voyage or Cohere key had the server's OpenAI model name sent to that provider; queries and documents now always resolve to the same provider and model. API keys for OpenAI-compatible gateways that do not start with `sk-` are no longer discarded, and untouched `.env.example` placeholder keys count as "not configured". One user's failing API key can no longer open the embeddings circuit breaker for everyone, and a rejected key is not retried.
- An existing Chroma store that failed to open was deleted and re-created even when the backup of it had failed. It is now reset only after a verified copy exists; otherwise startup stops with nothing deleted.
- Re-index and index repair dropped each document's matter tag, folder and metadata, and a provider error left a document "indexed" with no vectors behind it. Both now go through one path that keeps the tags and embeds the new chunks before the old vectors are removed: a provider failure leaves the document searchable as it was and is reported, and only a store failure after the swap marks the document failed.
- Citations: retrieval scores are reported as measured — no constant "95%"/"40%"/"50%" confidence, no "directly addresses the query" text on every passage, and a passage is no longer marked APPROVED because it shares three words with the answer (review status is left to the reviewer). The case-law guard now requires a reference to match a retrieved case's name party-for-party (two party words appearing somewhere in the sources used to be enough) and covers "In re", "Matter of" and "Ex parte" captions.
- Pinecone backend (now marked experimental): chunk text was truncated to 1,000 characters, selected-file chat and contract analysis crashed on it, and `has_document` always answered true.
- Connector sync imported the entire connected account whatever folder was chosen (`folder_id` was accepted and ignored). `POST /connectors/{type}/sync` now crawls only `folder_id` and refuses a request with neither a folder nor an explicit `sync_all: true`; Clio, whose listing is account-wide, refuses a folder instead of ignoring it. Synced files get the same size cap (enforced while streaming), type allowlist, magic-byte check and filename sanitisation as picker imports, are embedded with the user's own stored API keys, and each write a `document.upload` audit event. One file's 403/429 no longer aborts the sync, a failed sync always writes `connector.sync.failure`, an unchanged file is skipped on a repeat sync, and a provider error in the OAuth callback is a 400 rather than a 500.
- Filevine: a configured API key made the connector "connected" for every user, with the firm-wide key's access to every project. It is now off until `FILEVINE_ENABLED=true` and usable only by users with the Instance settings permission.
- Connector hardening: Microsoft no longer requests `Files.ReadWrite.All` and Google no longer requests `drive.file` on top of `drive.readonly` (existing connections keep their old grant until reconnected); disconnecting Box, Google or Dropbox revokes the token at the provider; a pre-isolation global credentials file is no longer adopted by whichever user loads first; picker downloads stop sending the bearer token once a redirect leaves the provider's origin, and file ids are URL-encoded; picker imports that could not be indexed are reported as failed instead of imported.
- The audit hash chain never linked: every entry written through the service pointed at its own provisional hash instead of the entry before it, so a production instance (`DEBUG` off, `AUDIT_HALT_ON_TAMPERING=true`) refused to restart once two entries existed and `GET /admin/audit/verify` always reported tampering. Entries are now written as hash version 3, linked to the entry stored before them, with the version inside the signature. Logs written by earlier builds need no migration: their signatures are still verified, linkage is enforced from the first version-3 entry onward, and a legacy-format entry after a version-3 one is reported as tampering. Startup verification now checks the most recent 1,000 entries in write order across daily files (it read the files newest-first and kept the wrong end).
- Audit log: timestamps are written as plain UTC (`...Z`, not `...+00:00Z`); the database mirror no longer fails on Postgres; `GET /admin/audit/logs` with `start_date`/`end_date` no longer answers 500 and a limited query returns the newest entries; a failed file write no longer leaves a gap in the chain (`AUDIT_FAIL_CLOSED=true` additionally fails the request); compressed archives are readable by queries and verification and are deleted at the retention horizon instead of accumulating. `GET /admin/audit/export` streams a date range as JSONL.
- `GET /metrics` answered 500 to every authenticated caller in production, and `GET /health` did the same whenever a valid bearer token was sent: both imported a module that does not exist (`app.utils.rbac`). `/health` also no longer answers 401 to a probe carrying an expired or revoked token — it returns the minimal response.
- PDF chat export and the DOCX/text-to-PDF conversion behind the document viewer returned 501 in the shipped image: `reportlab` was imported but never listed in `requirements.txt` / `requirements.lock`. The tests for both paths no longer skip when it is missing.
- The production containers could never pass their own healthcheck with a real domain: `ALLOWED_HOSTS` held only the public hostname while every healthcheck probed `http://localhost`, which TrustedHost answered with 400 — so Caddy (which waits for a healthy backend) never started. Loopback is now always an allowed host, the healthchecks have a start period, and the unified image probes through nginx so a dead nginx is noticed too. A `DOMAIN=localhost` trial no longer crashes on the "localhost origins not allowed" CORS check.
- Unified image behind Coolify/Traefik: nginx overwrote `X-Forwarded-Proto` with `http`, so auth and CSRF cookies were issued without `Secure`. The upstream value is now passed through; the health/ready/metrics locations forward the client address; static assets carry the security headers.
- `deploy/COOLIFY-SETUP.md` deployed the bare Dockerfile, which put `/app/data` on an anonymous volume that was replaced on every redeploy, and omitted required settings. It now uses the root `docker-compose.yml` (named volume), provisions Postgres and Redis, and lists every required variable; the `docker run` example no longer regenerates `SECRET_KEY` on every run.
- `scripts/restore_database.sh` reported "wrong BACKUP_ENCRYPTION_KEY" for any encrypted backup larger than a pipe buffer (a `head` under `pipefail`), and dropped the database before checking the data archive. Both archives are now verified in full (checksum, decrypt, gzip integrity) before anything is dropped.
- `scripts/setup_production.py` generated a file that failed its own `--validate` (and the app's startup): it now generates `AUDIT_HMAC_KEY`, `REGISTRATION_BOOTSTRAP_TOKEN` and `DISK_ENCRYPTION_ACKNOWLEDGED`, writes `.env` with mode 0600 without overwriting an existing one, uses the real connector callback paths, and no longer demands `OPENAI_API_KEY` or advertises a `--rotate-secret-key` flag that never existed.
- A `.env` containing compose-only keys (`DOMAIN`, `POSTGRES_PASSWORD`, `CORS_ORIGINS`, `ALLOWED_HOSTS`, …) crashed any non-Docker run (uvicorn, Alembic) with "Extra inputs are not permitted". Unknown keys are now ignored.
- `.env.example` shipped example values in active lines (`VOYAGE_API_KEY=your-voyage-api-key` with `EMBEDDING_MODEL=voyage-law-2`, connector client IDs, `MICROSOFT_TENANT_ID=common`), so following the quick start produced an instance that failed to index. Optional settings are now commented out.
- `NOTICE.md` did not match the dependencies that ship (42 wrong versions, 18 missing packages) and claimed to reproduce license texts. It is regenerated from the lock files and says what it is: a list.
- Uploading a file with the same name as an existing document deleted the existing one — a second "Engagement Letter.pdf" for another client destroyed the first. A new upload now replaces a document only when it is the same document (same remote file for connector imports; otherwise same owner, name, source, matter and folder), indexes the new copy before removing the old one, and audits the replacement.
- Deleting a document left its contract analyses and authority maps (with their verbatim quotes) behind, and ignored a failed vector delete, leaving the text searchable. Both are now removed with the document; if the vectors or derived rows cannot be removed, the delete fails and can be retried. "Clear all documents" follows the same path.
- Saving Settings could blank the playbook, practice profile and custom prompts: the UI loaded server settings only at page load, so a save after signing in sent empty values, and the server replaced the whole record. The UI now loads settings on every sign-in and blocks Save until they have loaded, and `PUT /settings/rag` merges — a field the request omits keeps its stored value, an explicit `null` clears it.
- Settings offered values the server rejects (vector stores that do not exist, slider ranges past the limits), four Advanced toggles were never sent, and validation errors rendered as "[object Object]".
- Judge Intel, Legal Tools and Case view calls did not refresh an expired session or prompt for sign-in; they showed generic failures after an hour. A failed chat query no longer clears the sources of earlier answers.
- `POST /legal-docs/extract-text` answers 422 with the reason when a file yields no text (a scanned PDF with OCR unavailable, a corrupt archive) instead of an empty success.
- Deleting a user whose stored API keys could not be removed stopped half-way with a 500. The keys are now removed first, and a key-store failure leaves the account untouched (503).
- Legacy Word `.doc` files were accepted but never indexed ("File is not a zip file"). They are now read directly. A corrupt, password-protected or scanned file fails with a reason shown on the document instead of a bare "failed". Windows-1252 text files no longer decode as garbage.
- The contract summary, risks and missing-clause list were produced from the first 8,000 characters of a contract, and the authority map from the first 18,000 characters of a filing and 14,000 of each opinion. Both now read the whole text in windows (bounded by the model's context window and configurable caps) and report anything left unread.
- The citation check could scan the wrong case: when a case's opinions could not be resolved it searched with an id from a different id space, and a name search took the first result whether or not it was the case named. It now reports "could not verify" or "not found" instead.
- Judge Intelligence could attach a namesake's Wikipedia biography. A page is used only when its title names the judge and its opening describes a judge. The metrics methodology no longer describes calculations that are not performed.
- Jurisdiction notes presented durations as caps where the law has none, and carried 2024 statutory figures with no date. Every rule now states when it was compiled, and figures that statutes adjust are flagged for verification.

### Security
- `/health` and `/metrics` validated a bearer token on their own, skipping the checks every other endpoint applies (token type, deactivated or deleted account, password change, live session). They now use the same validation and also accept the session cookie. The build fingerprint and release version are returned by `/health` only to an admin.
- Matters: any signed-in user, including a viewer, could create a matter and add colleagues to it; that now requires `matters.manage`. Adding a member no longer reveals whether an email address has an account, and deactivated accounts cannot be added. A matter member can read a colleague's shared documents and chats but no longer delete them — deletion is for the item's owner and the matter's owner.
- Audit trail: direct document uploads, document moves and folder deletes, matter create/delete and membership changes, contract-analysis reads, exports, redline and draft exports, comparisons, authority-map reads, chat-session and workspace-session reads and deletes, branding changes, and API-key saves and deletes are now recorded (ids only — filenames, matter and client names are left out).
- Branding: `logo_url` / `favicon_url` must be an `https://` URL or a same-origin path and colours must be hex; custom CSS is capped at 50,000 characters and can no longer load external resources (`url()` to another host, `image-set()`), since it is served to the unauthenticated login page. Uploaded SVG logos are served with a locked-down `Content-Security-Policy`.
- Text extraction and PDF conversion (`/legal-docs/extract-text`, `/convert-to-pdf`) ran on the event loop, so one large or OCR-heavy file stalled the whole single-worker server; they now run in a worker thread and require a document, contract or authority-map permission.
- Request bounds: pagination parameters have lower and upper limits, and the authority-map document text, redline overrides, long-draft plans, connector credential values and stored API keys are size-capped. The custom model endpoint must be an `http(s)://` URL.
- `decrypt_string` raises the documented `ValueError` on an authentication failure (wrong key or salt, tampered data) instead of leaking `InvalidTag` as a 500. Deleting stored API keys no longer reports success when the key store could not be rewritten.
- AI provider allowlist (`HIPAA_ENFORCEMENT_ENABLED` + `APPROVED_AI_PROVIDERS`): the check ran at one call site and inferred the provider from the model's name, so a model called "gpt-…" on a custom endpoint counted as OpenAI, and embeddings and the helper passes were never checked. It is now enforced on every embedding call and inside the shared chat-completion helper every feature uses (research chat, contract analysis, drafting, authority map, strategy, clause intelligence), plus the Anthropic and Gemini calls of research chat, against the endpoint that actually carries the request (`self_hosted` for a private address, a gateway by its hostname). The document analyzer's direct Anthropic call is checked as well, so no LLM or embedding call path is exempt.
- Chat no longer logs the text of users' questions, and a connector's own `matter_id` metadata can no longer end up as the access-control matter tag on indexed chunks.
- Dependencies: PyJWT 2.15.0, pypdf 6.19.0, urllib3 2.8.0 and oauthlib 4.0.0 clear 25 advisories that `pip-audit` reported against the shipped lock file. `cryptography` and `lxml`, imported directly, are now declared. CI audits and tests the hash-pinned `requirements.lock` (what the image installs) instead of `requirements.txt`.
- Bundled Redis runs with `maxmemory-policy noeviction` (was `allkeys-lru`): under memory pressure the LRU policy could evict revoked-token markers and lockout counters, reviving logged-out tokens.
- Sessions: a token refresh now continues the sign-in it belongs to instead of opening a new session, so the limits finally bind — a session ends 8 hours after sign-in (`SESSION_ABSOLUTE_TIMEOUT_HOURS`) however often it is refreshed, ends after 2 hours without a request (`SESSION_IDLE_TIMEOUT_MINUTES`), and the 5-session cap is real. A refresh is refused once its session has ended. Refresh tokens issued by earlier builds carry no session and are rejected: every user signs in once after upgrading.
- "Log out everywhere" (`POST /auth/logout/all`) left refresh tokens on other devices valid for up to 7 days. It now invalidates every outstanding access and refresh token of the account (`users.token_version`, migration 013). Admins get `POST /admin/users/{id}/sessions/revoke` to do the same for another user.
- Replay of an already-rotated refresh token ends every session of the account and writes a `security.session.hijack` audit event; rotation is atomic, so two concurrent refreshes with one token cannot both succeed.
- Token revocations and deleted-user tombstones are checked against the durable local store as well as Redis (they were checked only in Redis when Redis was up, and tombstones were not persisted at all); `revoked_tokens.jsonl` is pruned of expired entries instead of growing forever.
- Invited users must replace the admin-issued temporary password at first sign-in: until they do, every endpoint except change-password answers 403 `password_change_required`. `POST /auth/change-password` refuses a new password equal to the current one.
- First-account bootstrap: with `DEBUG` off, the first (admin) registration is refused until `REGISTRATION_BOOTSTRAP_TOKEN` is set and supplied, and concurrent first registrations can no longer both become admin. A closed instance answers "registration disabled" before checking whether the email exists. The boot-time "ensure an admin exists" step never promotes a deactivated account.
- MFA: a correct password no longer resets the failed-code counter (it allowed unlimited TOTP guessing with a known password); `/auth/mfa/enable`, `/disable` and `/recovery-codes` lock after repeated failures; disabling MFA requires the account password as well as a code; a TOTP code is accepted once. `REQUIRE_MFA=true` forces every password account to enrol before using the API, and `POST /admin/users/{id}/mfa/reset` lets an admin clear a lost authenticator.
- Azure SSO no longer attaches a sign-in to an existing local account on the strength of the token's (mutable, unverified) email claim. Accounts are matched on the Azure object id, which is now stored; an email match is accepted only for an unused, non-admin invite.
- Password reset cannot give an SSO-only account a local password, the email is sent after the response so timing does not reveal whether an account exists, and a mail-provider error no longer becomes a 500 for existing accounts. Passwords that are decorated common words (`Password123!`, `Welcome2024!!`) are rejected.
- Auth and CSRF cookies are always `Secure` when `DEBUG` is off, whatever `X-Forwarded-Proto` says.
- Rate limits are counted per route with identifiers collapsed, not per literal URL: every document, job or session id used to get a full quota of its own. Rules for routes that no longer exist were removed.
- Exception messages are no longer copied into the audit trail or, outside `DEBUG`, the application log (they can carry SQL parameters and document text); the log keeps the exception type, code locations and the error reference. Anonymous 401s are audited at most once per client per minute, so the audit trail cannot be flooded; sign-in attempts on a deactivated account are audited.
- `ENVIRONMENT=production` with `DEBUG=true` is a startup error.
- The page no longer contacts Google on load: the Google sign-in script is fetched only when the Google picker is opened, and fonts are bundled instead of loaded from Google Fonts. The Content-Security-Policy drops the font hosts and the AI-provider hosts (the browser never calls them), allows what the OneDrive picker needs (Microsoft Graph and the picker's form post), and is identical in the backend, `Caddyfile` and `nginx.unified.conf`.
- The settings-change audit entry records which fields changed, not their values (it used to store the playbook, practice profile and prompts in the audit log).
- Links built from CourtListener and Wikipedia data are restricted to `http(s)` everywhere, and connector OAuth popups are checked by exact origin (a prefix check accepted look-alike hosts).
- Backups: `scripts/backup_database.sh` refuses to write unencrypted archives unless `BACKUP_ALLOW_UNENCRYPTED=true`, writes a SHA-256 checksum for each archive, prunes S3 copies at the retention horizon, and pauses the backend while the data volume is archived. `backups/` is git- and docker-ignored, and the compose file blanks `BACKUP_ENCRYPTION_KEY` inside the backend container.
- CI: third-party actions are pinned to commit SHAs; `packages: write` and `security-events: write` are granted to the image-build job only; the gitleaks download is checksum-verified; `npm audit` (production dependencies) and ESLint run on every PR. The deploy examples only fire for a push to this repository's `main`, verify the SSH host fingerprint, and deploy the commit-SHA tag rather than `:latest`.
- The image ships `LICENSE` and `NOTICE.md`, drops unused Pango/Cairo libraries, and fails the build if the nginx privilege change does not apply (the step ended in `|| true`).

### Changed
- Documentation now describes what the product does. The README no longer says document content "never passes through a third-party SaaS": questions and document text are sent to the AI providers the operator configures, and `docs/subprocessors.md` lists every outbound flow (adding Pinecone, Wikipedia, the connector providers and the browser-side picker scripts). "HIPAA mode" is described as what it is, a provider allowlist. Claims of reranking, "SOC 2 compliant" revocation, sessions in Redis, and the event/route/table counts in `SECURITY.md`, `docs/architecture.md` and the ADRs are corrected; the ADRs carry a revision note.
- Vulnerability reports go through GitHub private vulnerability reporting; `SECURITY.md` and `CODE_OF_CONDUCT.md` no longer point at an environment variable for a contact address.
- `CONVENTIONS.md` and `CONTRIBUTING.md` describe the conventions the code actually follows (Zustand stores rather than per-feature hooks, `require_permission` rather than `require_roles`) and the real setup commands.
- Settings copy describes retrieval as it works: vector search with keyword rescoring of the candidates. No reranking model runs on a default install.
- Browser storage keys are prefixed `casecite_` (was `wl_`); existing values are migrated once.

### Removed
- Case Comparison (it called an endpoint that never existed), the unreachable providers and document-preview modals, the citation approve/reject workflow that saved nothing, the Batch Size setting, and 67 unused CSS classes.
- Dead backend code: unused encryption helpers (`generate_api_key`, `encrypt_file`, `decrypt_file`, `FieldEncryption`), `get_current_user_optional`, unused embedding/search/CourtListener helpers, `ChromaDB.clear_all`, the legacy in-memory connector sync status, 15 audit event types that were never emitted, and rate-limit rules for routes that no longer exist.
- `frontend/.npmrc` (`legacy-peer-deps`): the React type packages now match React 18.

## [1.2.0] - 2026-08-27

### Added
- Every generated artifact carries a review notice — "AI-generated. Verify every statement, citation and clause against the source documents and current law before relying on it." — in the UI (research answers, contract analyses, redlines, drafts, judge briefs, citation checks, authority maps, contract/case/tool chats) and as a closing paragraph in every Word, Markdown and PDF export. The drafting prompts that told the model to omit caveats and never suggest consulting an attorney are gone.
- Retrieved documents, CourtListener opinions and contract text are passed to the model inside explicit untrusted-content delimiters with a standing rule that instructions found inside them are data to be ignored (and mentioned); the user-query sanitizer no longer rewrites legitimate legal phrasing such as "act as attorney-in-fact".
- `NOTICE.md` lists every bundled third-party license (116 Python, 44 npm packages; none GPL/AGPL/SSPL). Contributions are accepted under the Developer Certificate of Origin (`git commit -s`), documented in CONTRIBUTING.md and the PR template.
- `API_TIMEOUT` (default 180 s) is now applied to every LLM and embedding client, with two SDK retries; previously the SDK's 600 s default was used and the setting was never read.
- Long-document drafting: set a target length in the Drafting workspace and the draft is planned first (sections, briefs, what each section must leave to others, shared definitions, style guide) from the full reference documents; after review, every section is drafted in parallel in its own context window with the full references and the whole plan, then a reconcile pass fixes cross-references, numbering and defined-term drift. `POST /contract-analysis/draft/plan` and `/draft/generate`.
- Revisions of long drafts are scoped: only the sections an instruction touches are rewritten (a selected clause routes straight to its section), the rest is left byte-for-byte.
- Background jobs report progress (`GET /jobs/{id}` → `progress: {message, fraction}`); the Drafting workspace shows it while sections are drafted.
- `LLM_CONTEXT_WINDOW` to declare the chat model's context size for custom/local endpoints whose names don't say.

### Fixed
- Drafting no longer silently truncates reference documents (and the draft being revised) at 40,000 characters — about ten pages; the budget is now derived from the model's context window.
- Redline .docx export renders from the text extracted from the stored original file instead of the vector-chunk reconstruction (which repeated text at every chunk seam); stored edits are re-anchored by their verbatim original text, unlocatable ones are listed in the document, multi-paragraph deletions are tracked per paragraph, and a character-level fidelity check refuses to produce a document whose plain + deleted text differs from the source.
- Chunk-seam de-duplication: consecutive vector chunks share an overlap run; contract analysis no longer sees (or quotes, or redlines) that run twice.
- Citation check ("Shepardize") no longer reports a case as good law after finding negative treatment language. The verdict is tri-state (`is_good_law: true | null`, never `false`), the most-cited citing opinions are scanned alongside the most recent, bare "rejected"/"erroneous" no longer count as negative, "overruled on other grounds" is a caution, and the not-a-citator caveat is shown with the badge. The tool is now labelled "Citation Check".
- Settings save failures are surfaced (toast + rollback) instead of closing the modal as if saved; wrong-password and other credential-endpoint 401s show the server's message instead of triggering a token refresh.
- The sidebar and Sources panel are reachable again on tablets and narrow windows: the responsive stylesheet is now wired to header toggles (with backdrop, Escape, and route-change close) instead of hiding both drawers with no way back.
- Contract review no longer rewrites span-less risk findings ("uncapped liability") as "Addressed" — only absence-type findings are put to the model for absence verification; risks keep their severity and are labelled unverified.
- Long-draft reconcile is checked before it is accepted: a `finish_reason` of `length` on any section or the reconcile pass is treated as a failure, every planned section heading must survive, and each section must stay within ±15% of its drafted length; otherwise the assembled sections are kept and the note names the section that failed.
- Dev/test SQLite no longer shares one connection across every session (`StaticPool`): a session's rollback could discard another session's uncommitted write, which is what made seed-then-request tests flaky.
- Operator runbooks work against the shipped stack: `scripts/backup_database.sh` runs on the host (the image never had `pg_dump` or the script), dumps Postgres through the bundled container and archives the `/app/data` volume in the same run; `scripts/restore_database.sh` decrypts `.enc` backups, quotes identifiers, restores the volume with `--data`, and stops/starts the backend around the restore. `docs/secret-rotation.md` is rewritten for the real stack (`casecite` role, derived `DATABASE_URL`/`REDIS_URL`, `up -d` instead of `restart`, a warning that rotating `SECRET_KEY` makes stored documents unreadable), and `--re-encrypt` is now real: `python -m app.utils.reencrypt` rewrites the BYOK key store, connector credentials, TOTP secrets and instance secrets under a rotated `ENCRYPTION_SALT`.
- `docker-compose.prod.yml` runs `CASECITE_IMAGE:CASECITE_TAG` (default: the GHCR image CI publishes) and the frontend is copied out of that same image, so `pull` + `up -d` deploys and `CASECITE_TAG=<sha> … up -d` rolls back; the VPS deploy example pins each deploy to the commit SHA and no longer forwards `GITHUB_TOKEN` into a remote shell. The bundled Redis healthcheck authenticates (an unauthenticated `ping` returned NOAUTH and passed); `git` is no longer installed in the runtime image.

### Security
- Deleting a user now also removes their connector OAuth credential files (revoking Google and Dropbox tokens best-effort first) and their per-user settings file; previously a departed employee's Google Drive refresh token stayed on disk and usable.
- The app refuses to start with more than one uvicorn worker regardless of vector backend — the session store, document registry and connector caches are process-local and two workers silently corrupt them. `docs/deployment.md` says so plainly; Pinecone alone does not lift it.
- `TRUSTED_PROXIES` is required in the root `docker-compose.yml` (the Coolify/Traefik variant); defaulting it collapsed every client to the proxy's IP, so one user's failed logins locked out the whole firm.
- Bespoke Serif (a Fontshare font whose license forbids redistribution) is replaced by Source Serif 4 (OFL) from the Google Fonts import the app already made.
- Validation errors no longer log the request body; submitted passwords and BYOK API keys stayed out of the container log stream only by luck before.
- `start.sh` no longer `chmod -R 755`s the data directory on every boot, which re-opened every 0600 secret file (instance secrets, BYOK key store, sessions, revoked tokens, audit logs, connector credentials).
- Audit entries are HMAC-signed over their full stored form (v2; v1 entries still verify), startup recomputes every recent signature instead of only checking linkage, and `AUDIT_HMAC_KEY_PREVIOUS` keeps a rotated key valid until the entries signed under it age out.
- Azure AD SSO mints tokens from the local account's roles rather than a hardcoded `attorney`; first-time SSO users get `AZURE_SSO_DEFAULT_ROLE` (viewer) or are refused when `AZURE_SSO_AUTO_PROVISION=false`; an admin-invited row is adopted by email.
- Logout resets every in-memory store (research, contracts, drafts, judge intel, documents, keys), and the login password is cleared from state after sign-in.

### Changed
- Every modal uses a shared accessible dialog shell (`role="dialog"`, `aria-modal`, focus trap, Escape/backdrop close); form controls carry labels; icon-only buttons and clickable rows are keyboard-reachable and named.
- Module docstrings and the OpenAPI description no longer describe the product as "SOC 2 compliant"; controls are described as what they are.

Local development is now `DEBUG=true` alone; production semantics are unchanged. Removed with it: `DEMO_DAILY_QUERY_LIMIT`, `DEMO_MAX_DOCUMENTS`, `DEMO_ACCOUNT_EMAIL`, `SALES_EMAIL`, the `X-Demo-Limit-*` headers, anonymous tool access (`require_permission_optional`), the public `GET /api/v1/config`, `docker-compose.demo.yml` and `.env.demo`. `/auth/demo/login` remains as a `DEBUG`-only dev login for `dev@localhost`. **Upgrading:** the removed keys are ignored with a startup warning if they are still in `.env` — delete them.
- Dead API surface with no caller: connector `upload_file` (four `NotImplementedError` stubs and four never-called implementations) and the `POST /connectors/{type}/upload` / `GET /connectors/{type}/files` routes; `DELETE /documents/all`, `GET /documents/stats`, `POST /documents/batch`; `POST /jobs/{id}/retry`; `DELETE /user/keys/delete` and `/delete-all`; the public `/clause-intel` router (the clause-intelligence service remains, used internally by contract analysis); `EncryptionService.re_encrypt()`.
- Frontend: 61 unused `default` exports, dead barrel re-exports, and the `export` keyword on 28 types nothing imported (knip: unused exports 73 → 0).
- Repo: `backend/pytest.ini` (folded into `pyproject.toml`), `deploy/DEPLOYMENT-GUIDE.md` and `deploy/DEPLOYMENT.md` (merged into `docs/deployment.md`), the Cloud Run deploy example (ADR-004 rules serverless out), `docs/screenshots/.gitkeep`, and the `para.db` pre-rename database fallback — rename `backend/data/para.db` to `casecite.db` on a dev machine that still has one.
- ~14,000 lines of code from removed products that were still compiled, seeded, and migrated: the `document_db` SQLite seeder package (templates, clause library, deadlines, workflows, discovery, Bates, e-filing — replaced by a static court list), the server-side judge brief / analytics / comparison endpoints the UI never called, 59 orphaned request schemas, 9 never-read database tables (dropped by migration 012), 15 response models for endpoints that did not exist, the dev-only debug endpoints, the unused half of `resilience.py`, the never-mounted session-timeout hook, and unused frontend types, barrels, and store actions.
